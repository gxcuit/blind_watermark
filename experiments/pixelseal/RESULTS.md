# PixelSeal 裁剪验证结果

结论：在这张图片上，用 PixelSeal 重新嵌入 64 位 ID 并加入 BCH 纠错，可以直接从与用户案例相同的裁剪图中恢复 ID。20 个随机 ID 全部恢复。PixelSeal 原始 256 位输出有少量错误，需要纠错层才能可靠获得完整 ID。

## 实测方法

2026-11-17，使用项目 `.venv`、Meta 官方 PixelSeal 权重及原版推理代码，在 Intel Core i5-10210U CPU 上运行，4 线程，无 CUDA。保持默认水印强度 `scaling_w=0.2` 和 JND。

原图是 `examples/pic/ori_img.jpeg`（宽 738、高 1108）。用户的 `embedded2.png` 与 `embedded.png` 的第 395 行至末尾逐像素相同。因此本实验对 PixelSeal 新生成的图片执行相同操作，保留 738×713 像素，即原面积的 64.35%。这是精确复现裁剪操作，没有在 Windows 编辑器中人工操作。

每次都保存图片后重新读取。解码器只接收裁剪图片，不接收原图、原尺寸、裁剪坐标或预期 ID，不补回原画布。官方模型内部把收到的图片缩放到其固定的 256×256 输入。

原有 `embedded2.png` 是 blind_watermark 生成的，无法用另一种算法提取其中的信息。两种方法的比较必须先分别嵌入水印。

## 同位置裁剪

| 载荷方式 | 未裁剪完整恢复 | 删除顶部 395 行后完整恢复 | 裁剪后原始错误数 |
|---|---:|---:|---|
| PixelSeal 原始随机 256 位消息 | 5/5 | 0/5 | 6～11 位 / 256 位 |
| PixelSeal + 64 位 ID + CRC32 + Reed–Solomon | 5/5 | 3/5 | 6～16 位 / 256 位 |
| PixelSeal + 64 位 ID + CRC32 + BCH | 20/20 | **20/20** | 2～16 位 / 256 位，均纠正 |

第一轮使用种子 20261117；第二轮使用种子 20261118，测试 20 个新 ID。不同编码轮次的 ID 也不同，并非逐个配对比较。

Reed–Solomon 按字节纠错。本例中的分散比特错误可能涉及超过其额度的字节。BCH(255,99)，设计距离 47，按比特纠错，可纠正码字中最多 23 个比特错误。编码内容是 64 位 ID、32 位 CRC、3 位固定零，加上校验位组成 255 位码字，再补 1 位未使用的零以适配 256 位接口。两种纠错层均由本实验额外加入，不能将其效果归为 PixelSeal 裸模型自带功能。

## 补充攻击

以下仅针对第二轮的第一个 ID `f7814f1508ad145c`，各测试一次，不代表整体成功率。

| 操作 | 保存尺寸 | BCH 前错误数 | ID 是否完整恢复 |
|---|---|---:|---|
| 同用户案例，保留底部 713 行 | 738×713 | 12 | 是 |
| 保留顶部 713 行 | 738×713 | 14 | 是 |
| 中心裁剪，保留约 50% 面积 | 522×784 | 0 | 是 |
| 中心裁剪，保留 25% 面积 | 369×554 | 9 | 是 |
| 用户裁剪后再缩小约一半 | 369×356 | 14 | 是 |
| 用户裁剪后再 JPEG 75 保存 | 738×713 | 14 | 是 |

未加水印的原图、其同位置裁剪图、旧算法生成的 `embedded2.png` 三个对照均未输出有效 BCH ID。三个对照不足以估计实际误报率；CRC 校验也不提供密码学认证。

## CPU 耗时与图片质量

第二轮同位置裁剪，模型提取耗时中位数 0.252 秒，BCH 解码中位数 0.138 秒；每次两者耗时之和的中位数 **0.386 秒**。该计时从模型已加载后开始，不含图片读取、Python 导入和模型加载。

嵌入耗时中位数 1.178 秒；PNG 图片 RGB PSNR 中位数 46.89 dB（范围 46.78～47.05 dB）。第二轮模型加载约 22.7 秒，不含 Python 导入，部署时可常驻进程复用模型。
